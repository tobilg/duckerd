# AdventureWorks example

A larger schema for trying DuckERD: Microsoft's AdventureWorks sample database, with 71 tables and 90 foreign keys, converted to DuckDB. Only the schema is included (tables, columns, primary keys, and foreign keys, no rows), since a diagram needs nothing else. The database is about 270 KB.

## Build and render

From the repository root, after `npm install`:

```bash
npx tsx examples/adventureworks/build.ts adventureworks.duckdb
npm start -- -d adventureworks.duckdb -o adventureworks.svg
```

`build.ts` refuses to overwrite an existing file; pass `--force` to replace it. `npm start --` runs the CLI from this checkout; with DuckERD installed globally, use `duckerd` instead.

The output takes the diagram's natural size, about 8700 × 4800 pixels. SVG output suits diagrams this size, since viewers can zoom without losing quality.

## Differences from the original

[`schema.sql`](schema.sql) is generated by [`convert.ts`](convert.ts) from `instawdb.sql`, the OLTP install script in [microsoft/sql-server-samples](https://github.com/microsoft/sql-server-samples/tree/master/samples/databases/adventure-works/oltp-install-script). The usage notes at the top of `convert.ts` show how to regenerate it.

- **One schema.** DuckDB does not support foreign keys between schemas, so the five original schemas (`Person`, `Sales`, `Production`, `Purchasing`, `HumanResources`) are merged into one. Table names are unique across them, so none are renamed. Each table's comment records its original schema.
- **Inline keys.** DuckDB cannot add keys with `ALTER TABLE`, so primary and foreign keys are declared inside each `CREATE TABLE`, and tables are ordered so referenced tables come first.
- **Types.** SQL Server types map to their closest DuckDB types: `money` to `DECIMAL(19,4)`, `uniqueidentifier` to `UUID`, `xml` and `hierarchyid` to `VARCHAR`, and `geography` and `varbinary` to `BLOB`. Computed columns become plain columns of their result type.
- **Names.** `AWBuildVersion."Database Version"` becomes `DatabaseVersion`, since Mermaid attribute names cannot contain spaces. The columns `Group` and `Primary` are quoted because they are reserved words in DuckDB.
- **Omitted.** Defaults, check constraints, indexes, views, procedures, and data.
